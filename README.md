# SKKM Connector COM

COM-обёртка над `SkkmConnector` — программной обёрткой над REST API **Сервера ККМ** для приложений,
которые не могут напрямую подключить .NET-сборку: **1С:Предприятие**, **Excel/VBA**, **VBScript**,
**PowerShell**, старый **VB6/Delphi** и любой другой язык с поддержкой COM.

Позволяет добавить печать чеков и управление ККТ без ручной сборки HTTP-запросов и JSON. Работа строится вокруг одного объекта `SkkmConnector`: заполняете свойства, вызываете метод, читаете результат из свойств.

# 1. Возможности

- **Полное покрытие REST API Сервера ККМ 4.0** — печать чеков, возвраты и коррекции, открытие и закрытие смены, X/Z-отчёты и отчёт о расчётах, внесение и выемка наличных, слипы, картинки, маркировка, фискализация, очередь печати, шаблоны, операции, а также администрирование (пользователи, настройки службы, пулы, добавление и изменение ККТ).
- **Простой доступ** — один объект `SkkmConnector`: заполняете свойства, вызываете метод, читаете результат из свойств — без ручной сборки HTTP-запросов.
- **Синхронный и асинхронный режим** — ждать ответ на кассе или поставить задание в очередь и опросить статус позже.
- **Состояние касс** — список устройств с сервера, сведения о ККТ, статус смены, счётчики, остаток наличных.

# 2. Требования

- **Платформа:** .NET Framework 4.8 (не .NET 6+ — COM-активация из 1С/VBA/VBScript работает только через классический .NET Framework), сборка **x86** (потребитель — 1С, Excel — тоже должен быть 32-битным);
- Права администратора — для регистрации сборки в реестре Windows;
- **Доступный Сервер ККМ 4.0 -** доступная служба печати (по умолчанию TCP-порт `4398`); если на сервере выключен анонимный доступ - токен авторизации пользователя.

# 3. Структура библиотеки

```
SkkmConnector/
├── Core/   — класс SkkmConnector: подключение, методы API, состояние, разбор ответов
├── Dto/    — публичные типы: позиции чека, оплаты, покупатель, перечисления, результаты
└── Data/   — внутренний HTTP-транспорт и контракты обмена с сервером
```

# 4. Варианты интеграции

Коннектор подключают через регистрацию в реестре Windows — код использования везде один: `CreateObject("RBSoftSkkm.SkkmConnector")` (или `Новый COMОбъект(...)` в 1С).

## 4.1. Сборка и регистрация

```powershell
cd SkkmConnector
dotnet build
cd bin\Debug\net48
& "C:\Windows\Microsoft.NET\Framework\v4.0.30319\RegAsm.exe" SkkmConnector.dll /tlb:SkkmConnector.tlb /codebase
```

Должно появиться: «Типы зарегистрированы успешно», «библиотека типов зарегистрирована успешно».

При каждой пересборке регистрацию нужно повторять — предварительно отменив старую:

```powershell
& "C:\Windows\Microsoft.NET\Framework\v4.0.30319\RegAsm.exe" SkkmConnector.dll /unregister
```

## 4.2. Проверка регистрации

Быстрый тест — обязательно из **32-битного** PowerShell (`C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`):

```powershell
$kkm = New-Object -ComObject RBSoftSkkm.SkkmConnector
$kkm.Host = "127.0.0.1"
$kkm.RunPing()
Write-Host "Ok:" $kkm.Ok
```

Если `Ok` вернулось без COM-исключения — регистрация прошла успешно.
