# Установка SkkmConnector

Разворачивает `RBSoftSkkm.SkkmConnector` как COM-объект на новой машине — для вызова из 1С 7.7 / 1С 8.x, VBA или любого другого позднего связывания. Занимает одну папку и один запуск от администратора.

## Перед началом

- **.NET SDK** (не только Runtime) — нужен, чтобы собрать проект (`dotnet build`). Ставится с сайта Microsoft, если ещё не стоит.
- **Windows с .NET Framework 4.8** — для запуска уже собранного коннектора; обычно уже стоит.
- **Права администратора** — нужны для записи в GAC, реестр CLSID и `machine.config`.

## Шаги

### 1. Собрать проект

Из папки `SkkmConnector` (там, где лежит `SkkmConnector.csproj`):

```powershell
dotnet build
```

Ключ строгого имени (`utils\key.snk`) уже в репозитории — отдельно генерировать ничего не нужно. После сборки вся папка `bin\Debug\net48` готова к регистрации: сама `SkkmConnector.dll`, её зависимости, `gacutil`, `reg.bat`/`unreg.bat` и файл политики биндингов лежат там рядом.

### 2. Запустить reg.bat от имени администратора

Дальше работаем внутри `bin\Debug\net48`.

Правый клик по `reg.bat` → «Запуск от имени администратора» (или запустите из elevated-консоли). Скрипт сам, без дополнительных действий:

- ставит зависимости и саму сборку в GAC;
- регистрирует COM-класс для 32- и 64-битных хостов;
- правит `ThreadingModel` на `Apartment` — нужно для 1С 7.7;
- добавляет binding redirects в `machine.config` — нужно для любого COM-хоста (1С, VBA), который не читает `.dll.config` сборки.

```powershell
.\reg.bat
```

### 3. Проверить активацию из PowerShell

```powershell
$kkm = New-Object -ComObject RBSoftSkkm.SkkmConnector
$kkm.Host = "127.0.0.1"; $kkm.RunPing()
$kkm.Ok
# True
```

### 4. Подключить из 1С / VBA

Если шаг 3 прошёл — из 1С коннектор создаётся стандартным способом, по ProgID `RBSoftSkkm.SkkmConnector`:

```
Ккм = СоздатьОбъект("RBSoftSkkm.SkkmConnector");
```

Перезапуск 1С после регистрации **обязателен** — COM-активация подхватывается только в новом процессе.

> **Обновление версии.** Если нужно накатить новую сборку коннектора на ту же машину — просто повторите шаг 2: `reg.bat` перерегистрирует всё поверх существующего (идемпотентен, старые редиректы и записи GAC не дублирует).

## Что в папке

| Файл | Назначение |
| --- | --- |
| `SkkmConnector.dll` | сам коннектор |
| `reg.bat` / `unreg.bat` | регистрация / полное удаление |
| `gacutil.exe` | установка сборок в GAC |
| `fix-binding-redirects.ps1` | правки `machine.config`, вызывается из `reg.bat` |
| `policy.8.0.System.Text.Json.dll` | publisher policy (доп. подстраховка) |
| `*.dll` (`System.*`) | зависимости `System.Text.Json` и рантайма |

## Удаление

```powershell
.\unreg.bat
```

От администратора же. Снимает COM-регистрацию и убирает сборки из GAC. Правки `machine.config` не откатывает — они безвредны для остальных приложений и обычно не мешают ничему другому на машине.

## Если что-то не заработало

**`0x80070002` — файл не найден**
Обычно значит, что `reg.bat` запускали не от администратора, или запускали не из скопированной папки целиком (не хватает соседних `.dll`).

**«Неудачная попытка создания объекта» в 1С 7.7**
Если это всплыло на старой версии сборки без фикса `ThreadingModel` — обновите DLL и перезапустите `reg.bat`; в текущей версии это чинится автоматически при регистрации.

**Изменения не видны после обновления DLL**
COM и 1С кэшируют загруженную сборку на время жизни процесса — закройте **все** окна 1С/приложения-хоста и откройте заново после повторного `reg.bat`.
